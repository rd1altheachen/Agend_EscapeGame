# 遊戲實作驗證

在遊戲程式碼、遊戲狀態、素材或部署改變時，驗證本次改動及受影響的既有行為。

## 遊戲專屬檢查
- 討論格位或索引時標明 0-indexed 或 1-indexed，必要時提供兩種表示的對照。
- 玩法規則使用關卡／資料屬性，不把單一關卡尺寸、數值或 ID 寫死在通用邏輯。
- 若要驗證 UI 流程，使用玩家實際操作路徑；不要直接改內部 state 來略過 UI 驗證。切換關卡或案例時完整建立乾淨 state。
- 保護已由使用者確認的版本和功能。修改前記錄要變更與要保留的行為；是否使用 tag 或分支依專案流程選擇。
- 推送素材前確認檔案受版本控制且路徑／大小寫正確。部署必須已獲授權，完成後核對線上目標。

回歸範圍依變更影響選擇；對核心流程作有意義的檢查，回報結果與未覆蓋部分，不要求每次重跑無關功能。
