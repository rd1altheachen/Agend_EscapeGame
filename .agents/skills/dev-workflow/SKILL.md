# 專案開發實作流程

適用於原型或功能實作、會改變規格所述行為的程式修改，以及已獲授權的部署。

## 核心要求
- 開始前依據目前核准的規格和決策。若實作、規格或使用者要求衝突，先請負責 owner 確認；不得自行把現有實作當成核准需求。
- 行為變更完成後，僅在任務範圍和權限允許時同步更新受影響的規格來源，並說明同步位置。不要因技能文字而擴大外部文件修改權限。
- 修改後選用能驗證本次行為的測試或檢查。自動化工具、solver 或產生器的結果，依風險以已知案例、獨立方法或人工推導抽查。
- 只有部署獲授權時才發布；部署後檢查實際線上目標，而非只憑本機結果宣稱完成。回報所驗證的範圍及未覆蓋項目。

規格同步與遊戲專屬驗證細節按任務使用相應技能；不重複套用同一份檢查清單。
